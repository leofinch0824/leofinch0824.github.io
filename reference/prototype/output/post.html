LIS 与树状数组的取舍

同一道最长上升子序列，朴素转移和树状数组优化之间差的往往不是速度，而是你想在题解里讲清楚什么。

2026 · 01 · 21 约 11 分钟 算法 / 数据结构

最长上升子序列（LIS）的定义很短：在一个序列里，找出最长的、严格递增的子序列。子序列不要求连续——这一点是全部麻烦的来源。

先别急着优化。把状态定义写下来：dp[i] 表示以第 i 个元素结尾的最长上升子序列长度。那么每一个 i 都要回头看它前面所有的 j：

dp[i] = 1 + max{ dp[j] | j < i, a[j] < a[i] } (1)

照着这个式子抄成代码，就是双重循环：

lis-naive.tsTypeScript
function lisNaive(a: number[]): number {
  const dp = new Array(a.length).fill(1);

  for (let i = 0; i < a.length; i++) {
    for (let j = 0; j < i; j++) {
      if (a[j] < a[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
    }
  }

  return Math.max(...dp);
}

这段代码的问题显然是 O(n²)。序列长度几千的时候它还能跑，再往上就彻底不行了。

慢在哪里

把内层循环要做的事情说清楚：给定一个前缀 a[0..i-1]，我们要在所有小于 a[i] 的值里，找最大的 dp。

关键是后半句。我们要的不是「前 i 个里最大的 dp」，而是「值小于 a[i] 的那些位置里最大的 dp」。这个「值小于」是一个前缀条件，而前缀条件正是可以用树状数组或线段树处理的信号。

树状数组：把 max 变成前缀查询

树状数组（Fenwick tree）平时用来做「单点加、前缀和」，但它其实只依赖两件事：一个满足结合律的运算，和一个单位元。max 满足结合律，单位元取 0——所以把加法换成 max，树状数组照样成立：

query(k) = max{ bit[t] | t ≤ k } (2)

于是整件事只剩下三步：

  1. 把所有出现过的值离散化，映射到 1..m 的下标；
  2. 对每个 a[i]，先查「下标严格小于它」的最大 dp，加一作为 dp[i]；
  3. 把这个 dp[i] 单点更新进树状数组。
lis-fast.tsTypeScript
function lisFast(a: number[]): number {
  // 离散化：把值域压到 1..m，树状数组只关心相对大小
  const rank = new Map(
    [...new Set(a)].sort((x, y) => x - y).map((v, i) => [v, i + 1]),
  );
  const m = rank.size;
  const bit = new Array(m + 1).fill(0);

  const query = (i: number) => {
    let best = 0;
    for (; i > 0; i -= i & -i) best = Math.max(best, bit[i]);
    return best;
  };
  const update = (i: number, v: number) => {
    for (; i <= m; i += i & -i) bit[i] = Math.max(bit[i], v);
  };

  let ans = 0;
  for (const x of a) {
    const i = rank.get(x)!;
    const best = query(i - 1) + 1;
    update(i, best);
    ans = Math.max(ans, best);
  }
  return ans;
}

复杂度是 O(n log n)，几十万的长度也在几十毫秒之内。

树状数组还是线段树

能写线段树的地方，多半也能改用树状数组——反过来不成立，但差别往往只体现在代码长度上。

所以真正的取舍不在性能，而在你要付出多少行代码：

  • 树状数组：一维、单点更新、前缀查询，不到二十行。它处理不了区间赋值、区间最值这类问题。
  • 线段树：什么都能做，代价是一百行左右的模板，以及每写一次题解就要重新解释一遍标记下传。
  • 如果问题只是「值域前缀 + 最值」，那没有理由选线段树。

我最后选了哪个

两版都写了，最后一并留在仓库里，各司其职：

  1. 题解正文用朴素版——它的转移式和 dp 定义一一对应，读者不需要先学会树状数组才能看懂递推。
  2. 提交代码用树状数组版——在评测机的时间限制面前，讲清楚是其次的。
  3. 如果这道题的规模只有几千，我甚至不会提树状数组。过早的优化在题解里比在代码里更贵。

以后再遇到「前缀条件上的最值」，先想想能不能离散化加树状数组；想不出来，再上线段树。这个顺序帮我省下的时间，比省下的那几毫秒多得多。
