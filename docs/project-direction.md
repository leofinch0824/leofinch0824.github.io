# 个人博客定位、阅读需求与正文技术栈

记录日期：2026-10-03

本文记录当前讨论形成的使用背景、需求和技术建议，作为后续迭代的依据。已确认需求、推荐方案和待验证事项分别标明；推荐方案不代表已经安装、实现或通过验证。

## 1. 使用背景与主题方向

### 已确认

- 项目用于部署个人博客，持续发布个人文章。
- 网站呈现服务于每篇文章的内容，读者也包括作者本人；需要兼顾初次阅读与长期回读。
- 文章会涉及技术分享、算法和类似论文中的数学公式，以及代码块等复杂排版内容。
- 阅读时的主要注意力应集中在文章内容上。视觉效果的目的是改善体验与聚焦程度，不能增加阅读负担。
- 希望确定适合长期维护、持续迭代的前端技术方案。

### 当前方向与未定范围

网站以个人文章和技术内容的清晰呈现为核心，视觉方向倾向安静、稳定、克制。尚未确定具体配色、字体、首页构图或现成主题，也没有将文章范围限定为某个技术领域。

## 2. 已确认的体验需求

### 首页、列表与文章导航

希望在以下位置考虑适量动态视觉效果：

1. 打开博客首页时。
2. 浏览、点击文章列表时。
3. 打开某篇文章时。

具体动画形式尚未确定。采用动效的前提是帮助理解操作和页面变化，同时保持内容易读；不能把“增加动画”直接等同于“改善阅读体验”。

### 文章正文

- 需要质量可靠的 Markdown 渲染与正文排版。
- 需要呈现技术文章中的数学公式，使用 LaTeX 数学语法。
- 需要代码块及语言语法高亮。
- 需要处理复杂内容与普通段落混排，避免公式、代码等破坏阅读节奏。

目前只确认数学内容主要类似论文中的公式，尚未提供真实文章样本。不能据此认定需要完整 LaTeX 文档支持，也不能认定公式兼容性已验证。

## 3. 阅读与动效的设计建议

以下为推荐原则，具体效果仍需页面验证：

- 内容立即可读，不等待开场动画或逐段入场。
- 动效以操作反馈和导航衔接为主；读者停下来阅读时，页面保持安静。
- 首页避免持续运动的装饰；文章列表可采用轻微的颜色、下划线等反馈，并兼顾键盘聚焦。
- 文章切换可尝试短而轻的过渡，但是否启用 Astro 的页面过渡能力应单独评估。
- 正文默认不使用逐段显现、滚动劫持或视差效果。
- 优先做好正文宽度、字号行距、中英文混排、对比度、图片占位与移动端排版。
- 动效需要考虑减少动态效果的系统偏好。

## 4. 推荐的正文技术栈

| 层次 | 推荐方案 | 作用与边界 |
| --- | --- | --- |
| 文章编写 | Markdown 为主，MDX 按需 | 普通技术文章使用 Markdown；需要嵌入组件时再使用 MDX |
| 内容组织与页面生成 | Astro + Content Collections | 组织文章元数据，生成文章列表与正文页面 |
| Markdown 扩展 | Unified / remark / rehype | 在 Astro 内容处理中接入数学等语法扩展，按项目版本配置 |
| 数学公式 | `remark-math` + `rehype-katex` / KaTeX | 解析数学语法并渲染公式，作为优先验证方案 |
| 代码高亮 | Astro 内置 Shiki | 提供按语言区分的语法高亮 |
| 代码展示增强 | Expressive Code，按需评估 | 文件名、复制按钮、重点行与增删标记；尚未确定采用 |
| 正文排版 | 专门设计的 CSS | 统一段落、标题、列表、引用、表格、代码和公式的阅读体验 |

推荐在构建时完成文章、公式和代码高亮的渲染，使阅读内容在页面打开时直接可用。公式仍需要配套样式与字体；复制按钮等行为可以使用少量客户端脚本。

### 数学公式的选择依据

KaTeX 是当前首选候选，适合优先验证求和、积分、上下标、矩阵、分段函数和多行对齐等公式。

它支持的是一定范围内的 LaTeX 数学语法，不能视为完整 LaTeX 排版系统。若真实文章涉及不支持的命令、自定义宏、特殊环境、自动编号或跨公式引用，应逐项确认，再判断是否需要额外插件或评估 MathJax。

### 代码块的选择依据

Shiki 作为基础高亮方案即可起步。若文章经常需要讲解重点行、显示文件名或标记代码增删，再评估 Expressive Code。扩展标记会增加文章对特定工具的依赖，应结合实际写作频率决定。

## 5. 当前实现状态与整体技术边界

截至本次讨论，项目依赖声明包含 Astro `^7.3.5`、MDX、RSS、Sitemap 等，页面仍接近博客模板。已有 Markdown / MDX 内容组织与基础代码高亮能力，尚未配置本文件推荐的数学公式处理方案。

当前项目事实以 [package.json](../package.json)、[Astro 配置](../astro.config.mjs) 和 [内容集合配置](../src/content.config.ts) 为准。

整体推荐基础仍是 Astro + CSS，必要的独立交互使用少量 TypeScript。当前已确认的文章、公式与代码需求不要求引入 Svelte、Motion、GSAP、D3 或 ECharts。这些工具保留为未来具体交互文章的候选，不列为当前默认依赖。

尚未启用 Astro `ClientRouter`。是否引入页面切换机制，需要结合实际体验及脚本、图表和动画的初始化与清理成本决定。

## 6. 后续验证与待定事项

下一步优先用一篇真实技术文章验证正文方案，而非继续扩充工具清单。检查内容应包括：

1. 行内公式、独立公式、多行推导和矩阵显示正确，行距与段落间距自然。
2. 实际使用的数学命令和宏兼容；是否需要公式编号、引用或算法伪代码环境得到明确结论。
3. 长公式、长代码、宽表格在手机上不撑破整页，内容仍可完整阅读。
4. 若加入复制功能，复制结果保留原始代码，不混入行号和展示标记。
5. 标题、列表、脚注、引用和中英文段落层级清晰。

这些是建议的验收条件，不代表项目已经完成相应实现或验证。主题样式、页面过渡、Expressive Code 和数学扩展能力均待后续具体确认。
